SQL queries (the SQL page, exports, MCP and SQL connections from BI tools) answer in about a second instead of five to ten: a warm query worker runs each query in its own process instead of starting a Kubernetes Job for it, and a query it has no room for still runs as a Job. The Helm chart deploys it by default (`queryWorker`), sizes its slots from the pod's memory and scales it on CPU. One person may now run up to 100 queries at once instead of 3 (`queryWorker.maxActivePerPerson`).
