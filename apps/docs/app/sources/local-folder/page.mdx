# Mounted Folder

<SourceFacts type="LOCAL_FOLDER" />

The simplest source there is: point Classifyre at a **folder** and it scans what
is in it. With the [all-in-one Docker image](/deployment/docker/) that's a
directory you bind-mount from your own machine; in Kubernetes it's a volume
mounted into the cluster — a file share, a NAS export, a migrated archive.

## What you need to connect

A **path, as the scan sees it** — not as your file browser sees it. With Docker
that is the container-side path of a bind mount (`-v ~/case-files:/data/case-files:ro`
means you enter `/data/case-files`); in Kubernetes it is the `mountPath` the
chart's `api.localFolders` gave it.

There are no credentials: the scan reads the filesystem with the permissions of
the process doing the scanning. That's the whole security model, so be
deliberate about which folders you expose — and mount them read-only.

## What Classifyre reads

Every file below the folder, subject to the traversal controls:

| Control | What it does |
|---|---|
| **Max depth** | How far below the folder to descend |
| **Include hidden** | Whether dot-files and dot-directories are scanned |
| **Follow symlinks** | Off by default — link loops are not detected |
| **Extension allow / denylist** | Narrow it to the file types you care about |

## Worth knowing

- **A mounted network share behaves like a local folder**, so SMB and NFS
  exports can be scanned without a dedicated connector.
- **Deleted files are noticed.** A file that disappears between scans is marked
  deleted, and the findings it produced can be resolved automatically.
